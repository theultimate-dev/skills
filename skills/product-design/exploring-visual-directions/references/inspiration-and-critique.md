# Inspiration and critique

## Research a question

Inspect existing project assets, prior directions, and references supplied by the user first. Then browse a small set of relevant public examples if they can resolve a design question: how to scan dense content, how to build a reading hierarchy, or how to make a primary action clear.

For each useful reference, record its source, the observed principle, why it fits this audience, and what you would change. A reference is not a license to reproduce proprietary assets or a distinctive identity. Do not treat current popularity as proof that a pattern fits the task.

If no browsing or assets are available, work from explicitly stated design hypotheses and say so. Do not fabricate reference sites or pretend a mood description is a researched finding.

## Contrast on meaningful axes

Choose a few axes that matter for this product: reading versus scanning, restrained versus expressive, sequential versus exploratory, sparse versus dense, or image-led versus text-led. Explain the tradeoff; neither end is universally better.

Keep the same representative content and primary task across alternatives. Do not make a preferred option look better by giving it shorter text or removing difficult states. Where UX structure is already agreed, vary its visual expression rather than silently changing the behavior.

Distinctive work can use familiar controls. Avoid novelty that hides navigation, obscures labels, weakens contrast, or interferes with reading. Gradients, cards, serif type, large headings, and animation are tools, not mandatory ingredients or prohibited clichés.

## Critique the rendered result

Compare audience fit, task clarity, hierarchy, reading comfort, density, rhythm, responsiveness, accessibility risks, and fit with project constraints. Describe observations before recommendations: “The heading consumes most of the narrow viewport and pushes the topic filter below the first guide” supports a concrete revision.

Keep judgments provisional where evidence is missing. “This should help readers scan titles” is a hypothesis; “readers found guides faster” requires actual observation. A prototype review cannot establish global uniqueness or production accessibility conformance.

Summarize what to retain, what to change, and what needs the user's decision. For combined directions, rewrite the resulting brief with one coherent hierarchy and token set. Do not leave contradictory layout or font instructions for the next agent to reconcile.
