## [0.1.0] - 2026-11-18

### Added

- `recovering-built-architecture` skill: answers "what is really there?" for an application nobody has drawn. It reads manifests, entry points, configuration, infrastructure files and schema, and writes dated context and container views that give the evidence for each element and relationship, a file and line where the code shows it, and mark what is assumed. It keeps apart what the code shows, what only deployment configuration says and what only the running system could confirm, describes a part by what its code does when its name says otherwise, and lists the blind spots with what would settle each.
- `evaluating-architecture-risks` skill: takes a critical look at a problem, a design or a proposal before a consequential change. It restates the question without the solution you named, picks three to five measurable scenarios, and traces each through the views element by element. Then it looks for what the scenarios miss: single points of failure, each dependency slow or down, sensitive data crossing a trust boundary, and a short premortem. You get a dated risk review: a verdict per scenario, risks ranked and pinned to elements with cause and evidence, the trade-offs, and the next check for each top risk. It says so when the problem needs no architecture change.
- `exploring-architecture-options` skill: answers "what are our options?" for a choice about the system as a whole, including a system that does not exist yet. It checks what the code and the decision log already settle, then sketches two or three options that differ in kind, one of them the smallest change that could work, each as a view at the same level, and says so when the constraints leave only one. It traces the same scenarios through each and gives you a matrix with a sentence per cell instead of scores, a recommendation, and what would reverse it. You pick in your own words; the study records the pick and offers a decision record, and until you pick it says the choice is waiting.
- `simplifying-system-architecture` skill: answers "can this be simpler?" for a system that feels heavier than its job. It asks of every component, hop, store and technology what breaks if it goes, and names the guarantee each one gives from the code and configuration, not from its name. It proposes only the removals and merges that keep every guarantee, re-traces every scenario through the result, and says where the complexity moved. You get a verdict for each scenario and constraint, what to measure first, and before and after views when the study proposes a change. It tells you when nothing should change. You accept, narrow or decline, and the study records your answer.
- `drawing-architecture-views` skill: draws one question about your system as one view, a Markdown file with a Mermaid diagram and tables that tie every element and relationship to evidence, and keeps the index of views and studies. It explains the architecture to a named audience with a short guide to the views that already exist. It builds `architecture.html`, one page that shows every view and study with pan, zoom, light and dark, and any two views side by side, so nobody installs a tool to read your architecture. The page treats every view as untrusted text: it never reads a view's text as HTML, makes only relative, in-page, http, https and mailto links clickable, and runs only its own scripts and the pinned Mermaid file, which it checks against a known hash. A bundled bash script rebuilds the page from the Markdown files, the page reports which views drew, and its Save button makes a copy that opens with no network, for sending to someone outside.
- What to expect from a recovery, a risk review, an options study or a simplification study: an analysis to check, with its evidence, not a result. Each one is written by a model and gets a second pass that tries to break it before you see it, by a separate agent where the harness can start one and by the author's own second read where it cannot. That pass catches errors and not all of them: in the trials behind this release, a recovered view could still cite a line that shows only part of what its row says, a study could still repeat in one place a claim it had corrected in another, and an options study could still hold a verdict that its own timing table contradicts. Read the evidence cells of a recovered view and the Falsification pass section of a study before you rely on a verdict.
